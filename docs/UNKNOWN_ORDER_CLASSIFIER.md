# Режим определения неизвестного заказа — предложение владельца, 26.11.2026

## Интерфейс
Если входящая карточка содержит «Пассажир», но надежно подтвержденный тариф не найден, вместо автоматического EV включить расширенную плашку. Заголовок «Пассажир» и фиолетовая надбавка. Три строки «возможно Электро», «возможно Корпоративный», «возможно Fasten», в каждой две колонки «яндекс» и «на руки». Утвержденные темный фон, толстая желтая рамка, крупные цифры без разделителей и валюты. Обычные заказы — прежняя компактная плашка. Не закрывать кнопки приема, сохранить перемещение и сворачивание. Если модель цены не подтверждена, показывать прочерк/диапазон, не выдумывать ставку. При явном подтверждении источника/тарифа свернуть в обычную плашку.

## Разделение признаков
Хранить независимо: тариф/класс (EV, K+, BS и т.д.), источник (Yandex Go/Fasten/unknown), оплата (corporate/cash/card/unknown). Корпоративная оплата не отдельный взаимоисключающий класс. Возможны другие неизвестные заказы; три гипотезы не исчерпывающие. Исключить автоматическое присвоение EV только по слову «Пассажир». Учитывать доступные водителю тарифы как дополнительное свидетельство, не как безусловное доказательство. Официальная справка Алматы https://pro.yandex.com/kz-ru/almaty/knowledge-base/taxi/income-diff/order-types сообщает, что для водителей корпоративные ставки не отличаются от обычных; не вводить произвольный корпоративный коэффициент. https://pro.yandex.com/kz-ru/almaty/knowledge-base/taxi/news/tarif-electro-almaty — отдельный тариф Электро и условия доступности. https://fasten.com/legal/tou — отдельный сервис в Казахстане; проверить актуальные ставки каждого класса Fasten до численного расчета. Ставки из прежних публикаций не выдавать за текущие.

## Анализ цены и обучение
Один достоверный полный маршрут А→Б (все остановки), адаптивное время, надбавка один раз; разные подтвержденные тарифные модели и комиссии. Для корпоративного варианта использовать известный базовый класс либо диапазон классов, без выдуманных доплат. Для Fasten при неизвестном классе диапазон по подтвержденным доступным классам. Фиксировать прогнозы до принятия, цену при принятии и итог отдельно. Близость итоговой цены к гипотезе — слабое свидетельство, не доказательство источника: совпадающие тарифы, округление, ожидание, дополнительные сборы и скидки могут мешать. Не обучать на собственных догадках. Подтверждать метку по деталям завершенного заказа/явной надписи или добровольному подтверждению водителя. Если метка не подтверждена — оставить unknown; хранить ранжирование кандидатов отдельно.
Цифровой отпечаток: только разрешенные доступные узлы карточки Android (viewIdResourceName, className, безопасные категории contentDescription, относительное расположение, тип/форма/цвет значков, наличие отдельной плашки, число остановок, тип надбавки), версия Яндекс Про, язык, размер экрана. Не собирать рейтинг, имена, телефоны, адреса и идентификаторы пассажиров; не передавать сырые скриншоты на сервер. Нормализовать координаты элементов относительно карточки; отсутствие узла не равно доказательству класса. Первоначально локальные правила, затем классификатор по подтвержденным меткам, калибровка уверенности и отказ при неоднозначности. Отдельная оценка точности по тарифу/источнику/оплате и версиям интерфейса; тест на новых заказах. Не включать автоклассификацию при недостатке подтвержденных примеров.

## Приемка
1. «Пассажир» без тарифа не становится EV; явно известный EV/K+/BS не меняется.
2. Три гипотезы, отсутствие ставки не заменять фиктивной ценой; корпоративный может совпадать по цене с другим вариантом.
3. Прогнозы заморожены до факта; одинаковая цена двух гипотез не разрешает выбор.
4. Подтверждение источника/тарифа/оплаты раздельно, неизвестные случаи исключены из обучения меток.
5. Никакого сбора рейтинга пассажиров, скрытых API, автоматического принятия заказов. Проверить интерфейс на реальном Xiaomi и Android 10/14/16.
Статус: проектное требование и визуальная концепция. Реализация, актуальные сетки Fasten, валидация классификатора и APK еще не готовы.
