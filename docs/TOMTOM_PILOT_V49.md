# TomTom: практический пилот v49
Дата 26.11.2026. Основание: согласованное испытание третьего источника ETA. Никакой замены действующего ААЦ и ценовой плашки.

## Реализация
- patches/tomtom_pilot_v49.py добавляет TomTomRouter.kt, TomTomMetrics.kt, TomTomPilot.kt и тест TomTomMetricsCheck.kt, отдельный пункт «TomTom · тест пробок» в основном меню.
- HTTPS Calculate Route v1: traffic=true, computeTravelTimeFor=all, routeRepresentation=summaryOnly, routeType=fastest, travelMode=car. Поддерживаются упорядоченные точки в клиенте; UI использует исключительно две заранее заданные неперсональные тестовые координаты Алматы (оба направления). Не передаются адреса/координаты пассажиров, идентификаторы заказов или GPS телефона.
- Один OkHttpClient, callTimeout 2 с, асинхронный запрос, без повторов и перенаправлений; 20 ручных запросов на окно, не является глобальной квотой аккаунта. Ключ тестового Freemium вводит водитель, не в APK/Git/на диск; закрытие окна отменяет запрос и очищает поле. Не писать ключ, URL и координаты в Logcat; только статус/задержка. 
- BRouter и TomTom запускаются параллельно для одного тестового направления. UI показывает км, ETA, свободное время, историческое время, дорожную задержку, задержку API; ответы TomTom не пишутся в историю или обучение. Отсутствующий показатель — прочерк, не ноль; валидация основных метрик, HTTP 401/403/429, таймаут/сеть, ответ ограничен размером. 
- Входящие заказы не вызывают TomTom. Нет возврата к расчету по прямой, нет изменения действующего расчета тарифов, комиссий, времени Яндекс/BRouter, CatBoost или автоматического принятия.
- Официально Routing API v1 поддерживает Казахстан и real-time traffic; Freemium — 20 000 запросов маршрутизации в месяц на опубликованных условиях, после лимита блокировка до обновления при Freemium. Проверять активный план аккаунта, не подключать платный тариф без решения владельца.
- Для пилота выбран v1 в соответствии с предоставленным кодом. TomTom рекомендует Orbis для новых долгосрочных интеграций; оценить v3 отдельно, не смешивать карты разных поколений.

## Приемка
1. CI сборка APK v49 и модульные тесты метрик. Проверка Android API 29/34/36. 
2. Ввести собственный тестовый ключ на телефоне, открыть пилот на остановке. Выполнить оба направления в разные часы. Проверить реальные данные, точность и latency; отсутствие ключа, неверный ключ, отключенный интернет, ограничение квоты.
3. Сравнить маршруты и ETA на одинаковых A/B и всех остановках, не считать различие маршрутов доказательством пробок. Изучить альтернативные маршруты и задержки. 2 секунды — лимит сетевого запроса, не гарантия всей обработки заказа.
4. До использования реальных заказов и хранения/обучения на ответах TomTom проверить договор, права на данные пассажиров, обработку/локализацию данных Казахстана и ограничения хранения/ML. Для коммерческого решения — серверный шлюз с секретом, аутентификацией, дедупликацией, общей квотой и запретом платного перерасхода.
5. Только после положительного теста, разрешения на данные и валидации — теневой режим входящих заказов, независимые метрики Яндекс/BRouter/TomTom, строгое сопоставление полного маршрута и остановок, дедлайн 2–2,5 с, отмена устаревших запросов, никаких блокировок первой цены. Не менять цену по позднему ответу. CatBoost обучать на подтвержденных фактах, TomTom-метрики только при разрешении лицензии. Включать в ААЦ только при измеримом улучшении на независимой выборке.
6. Ключ TomTom пока не предоставлен. Реальный вызов и точность пробок Алматы не подтверждены. Это тестовая интеграция, не готовый третий источник цены.
